# Purposeful workflow motion

## Motion thesis

The Image Workbench acknowledges a new processed preview by tracing its frame once. The image itself remains visible. This indicates preview availability, not successful watermark removal.

| Interaction | Treatment | Budget |
| --- | --- | --- |
| Processed image loads | A clipped two-pixel accent frame traces across and fades | 460ms, once per mounted output URL |
| Drag enters/leaves uploader | Solid boundary, accent icon, slight icon compression | 120ms color; 160ms transform |
| Keyboard focus on uploader | Same boundary and icon colors, with existing focus outline | 120ms color |
| Progress changes | Fill translates to the current value | 200ms transform only |

The existing 500ms fade/slide on the entire result workspace and metadata panel was removed. Content is immediately visible and actions never wait for animation. No dependency, animation timer, or processing delay was added.

## Reduced motion and repeated use

- Reduced motion shows a static accent frame on the loaded output and a solid upload boundary. Icon compression and frame tracing are limited to `prefers-reduced-motion: no-preference`.
- Existing reduced-motion handling still minimizes other transitions and stops repeated loading movement. Text and numeric progress remain available.
- The preview is keyed by its object URL; reprocessing mounts a fresh preview. Locale changes and unrelated renders retain its loaded state and do not replay the arrival.
- The frame begins on image load and resets on image error. Removing the preview removes its CSS animation without cleanup timers.
- The overlay ignores pointer events. Image content, accessible names, and download behavior remain available throughout.
- The new effects have no loops, layout-property animation, blur, or persistent `will-change` layers. Clipping is bounded to the preview frame.
